# 输出模板

按问题类型选择模板。**不要**为了显得完整而套用大模板：用户只问"某条怎么规定"，
就给条文原文 + 条号 + 一句话要点。

所有模板共同遵守：
- 引用的每个条号都必须已经用 `law.py article` 读到原文；
- 涉及金额、期限、比例时写出算式或明确数字；
- **个案（模式 B）必须先按 `intake-questions.md` 提问收集事实，再套用下面的模板**；
  信息不全时在开头加「**本回答基于以下假设**」，说明假设不成立时结论如何变化；
- **每个模板的最后都要附「总结回答」**（见文末）；
- 结尾必须有免责声明（可精简为一句话）。

## 总结回答（**所有模式都必须给，放在回答最末**）

综合回答（或精简回答）之后，另起一段「总结回答」，用加粗小标题分段，
控制在用户 **30 秒能读完**的长度。它的作用不是重复，而是**压缩成可执行的结论**：
用户只读这一段，也知道自己处于什么处境、能拿什么、该做什么。

```markdown
### 总结回答

**你的情况属于**：<一句话定性：法律关系 + 性质>
　例："3 年期劳动合同被公司在第 4 个月单方解除，且拖欠工资"

**最关键依据**：<2～4 个条号，带法规简称>
　例：《劳动合同法》第 38 条第(二)项、第 46 条第(一)项、第 87 条

**你能主张**：
- <项目一>：<金额 / 算式 / 权利>
- <项目二>：<金额 / 算式 / 权利>
- 合计约 <金额>（区间或"以实际工资流水为准"）

**最大风险**：<1～2 个真正会翻车的点>
　例："公司若拿出你签字的录用条件与考核不合格证据，'违法解除'可能不成立"

**现在就要做**（按时间排序）：
1. <今天 / 立刻做的事>
2. <本周内做的事>
3. <下一步（谈判 / 仲裁 / 投诉 / 委托律师）>

**时效提醒**：<起算点 + 期限>
　例："自劳动关系终止之日起 1 年内申请劳动仲裁（劳动争议调解仲裁法第 27 条）"
```

**写作要求**

- **可独立阅读**：不依赖前文也能看懂；
- **不引入新主张**：总结里出现的每个结论，前文都必须已经论证并给出条号；
- **金额可核验**：写出基数、月数、算式，或明确说明"待补数据后计算"；
- **风险要具体**：写"对方手里的某份签字文件""某项地方标准未核验"，不写"存在一定风险"；
- **动作可执行**：写"今天就发书面催告函并保留 EMS 凭证"，不写"及时主张权利"。

**模式 A（纯条文查询）的简化版**：可只用一句话收尾，例如——

> **一句话总结**：本条允许……，但须同时满足……（第 X 条、第 Y 条）；若你是……情形，还需注意……。

## 写作禁忌

| 不要写 | 要写 |
| --- | --- |
| "根据相关法律规定" | "《劳动合同法》第八十七条" |
| "一般来说应该能赢" | "在<要件>成立且证据充分的情况下，请求<具体金额>有较大支持空间；但<风险点>" |
| "法律规定赔偿 2 倍" | "违法解除赔偿金为经济补偿标准的 2 倍（第 87 条）" |
| "第577条" | "第五百七十七条"（民法典条号用中文数字） |
| 只给结论不给条号 | 结论 + 条号 + 原文 + 要件 |
| 把旧公司法条号当现行法 | 明确标注版本与施行日期，必要时说明新旧法衔接 |
